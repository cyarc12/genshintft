# 元素自走棋 Demo：体系说明与经济、等级系统接入指南

## 1. 项目用途

这是一个浏览器本地运行的 8×7 六边形元素自走棋战斗原型，当前重点是：

- 双方自由布阵、备战席与无限棋子仓库；
- 自动寻路、索敌、普攻、回蓝、自动施法；
- 五种元素、元素附着、七种元素反应；
- 十名角色、召唤物、领域、护盾、治疗和持续状态；
- 实时伤害、承伤、治疗和护盾统计；
- 战斗结束返回备战时保留上一场记录，下一场开始时清空；
- 本地保存最后一次阵容和站位。

入口文件是 `index.html`。项目不依赖服务器、构建工具或第三方运行库，直接用浏览器打开即可。

## 2. 文件结构

```text
auto-chess-demo/
├─ index.html                         # 全部界面、配置、战斗逻辑和 Canvas 动画
├─ 体系说明与经济等级接入.md             # 本文档
├─ 打开说明.txt
├─ assets/
│  ├─ avatars/                       # 角色头像
│  ├─ elements/                      # 元素图标
│  ├─ reactions/                     # 元素反应图标
│  ├─ summons/                       # 召唤物图标
│  └─ status-*.svg / broken-shield.svg
├─ preview/                          # 设计过程中的预览与参考素材，不影响运行
└─ tools/                            # 素材处理辅助脚本，不影响运行
```

当前原型为了快速迭代，将所有代码放在一个 HTML 文件中。继续扩展经济和等级系统时，建议至少拆成 `data/`、`battle/`、`systems/`、`ui/` 四层，但拆分前应先保持现有行为不变。

## 3. 当前战斗流程

1. 进入备战阶段，读取浏览器本地保存的阵容。
2. 从右侧无限仓库拖出任意角色或木桩。
3. 棋子落在哪一方棋盘或备战席，就属于哪一阵营。
4. 开始战斗时保存最后站位，并重新创建干净的战斗运行时单位。
5. 每 0.05 秒推进一次固定步长战斗逻辑。
6. 单位自动索敌、寻路、普攻、获得法力并自动施法。
7. 一方棋盘没有存活单位时结束战斗。
8. 返回备战后恢复开战前站位，并保留上一场统计与战斗记录。
9. 再次开始战斗时清空上一场统计与记录。

备战阵容使用浏览器 `localStorage` 保存，键名为：

```text
element-auto-chess-formation-v4
```

保存字段：`id`、`name`、`team`、`row`、`col`、`onBench`、`benchIndex`、`inWarehouse`、`warehouseIndex`。

## 4. 棋盘与交互

- 棋盘：8 行 × 7 列六边形格。
- 红方半场：第 0～3 行。
- 蓝方半场：第 4～7 行。
- 双方备战席：各 10 格，备战席单位不参加战斗。
- 仓库：包含十名角色和一个木桩，是无限复制的调试目录。
- 长按拖动：移动棋子；拖到已有友方棋子的位置会交换。
- 无效位置：棋子保持原位。
- 双击：在棋盘和备战席之间自动寻找空位。
- 右键场上或备战席棋子：删除该实例，相当于放回无限仓库。
- 双方棋盘各有一键清空按钮。
- 单击棋子：右侧区域显示该阵营配色的动态角色面板，并覆盖战斗记录。

## 5. 单位数据结构

运行时单位由 `makeUnit()` 创建。重要字段如下：

| 类别 | 字段 |
|---|---|
| 身份 | `id`、`name`、`team`、`element`、`weapon`、`isDummy` |
| 位置 | `row`、`col`、`onBench`、`benchIndex`、`inWarehouse`、`warehouseIndex` |
| 面板 | `hp`、`maxHp`、`atk`、`as`、`critRate`、`critDamage`、`range`、`def` |
| 资源 | `mp`、`maxMp`、`skillReady`、`skillBlocked` |
| 战斗 | `target`、`attackCd`、`moveCd`、`motion`、`alive`、`flash` |
| 元素状态 | `attach`、`effects`、`freezeStack`、`hardFreeze` |
| 技能计数 | `skillStage`、`hutaoAttackCount`、`nilouCastCount` 等 |
| 统计 | `damageDealt`、`damageTaken`、`damageByType`、`takenByType`、`healingDone`、`shieldingDone` |

重要区分：

- `pieceTemplates`：角色目录定义。
- 仓库中的单位：无限模板入口，不应该直接成为正式经济系统中的“玩家资产”。
- 拖出的字符串 `id` 单位：真正的棋子实例。
- `summons`、`ozSummons` 等：战斗召唤物，不是可购买棋子。

## 6. 武器定位与基础数值

| 武器 | 定位 | 生命 | 攻击 | 抗性 | 基础攻速 | 距离 | 特性 |
|---|---|---:|---:|---:|---:|---:|---|
| 双手剑 | 坦克 | 1200 | 25 | 50 | 0.8 | 1 | 同距离索敌时优先被选择，具有嘲讽倾向 |
| 单手剑 | 战士 | 1100 | 50 | 40 | 1.0 | 1 | 生命高于 50% 时 +20 攻击；否则获得 15% 吸血 |
| 长柄 | 近战输出 | 1000 | 60 | 30 | 1.1 | 2 | 被当前目标以外的敌人攻击时减伤 15% |
| 法器 | 法术输出 | 800 | 65 | 20 | 1.0 | 4 | 每秒自动回复 5 法力；普攻造成自身元素伤害 |
| 弓 | 远程输出 | 700 | 70 | 15 | 1.0 | 5 | 每远离目标 1 格，增伤 3% |

全部普通角色初始具有：

- 20% 暴击率；
- 140% 暴击伤害；
- 普攻命中回复 10 法力；
- 进入技能特殊状态时默认不通过普攻回蓝，明确写有例外的角色除外；
- 攻速上限 5.0。

## 7. 伤害公式

当前所有伤害类型，包括物理，都走同一个“抗性值”。物理被视为一种伤害属性。

基础结算：

```text
抗性结算后伤害 = 原始伤害 × 100 / (100 + 有效抗性)
最终非真实伤害 = 抗性结算后伤害 × max(0, 1 + 增伤合计 + 目标承伤修正合计)
暴击伤害 = 最终非真实伤害 × 暴击伤害倍率
```

规则：

- 增伤、减伤和易伤采用加算。
- 抗性不会低于 0。
- 对应元素减抗为 30%，全元素减抗为 15%。
- 同一伤害类型上，高减抗覆盖低减抗，不叠加。
- 例如火元素同时受到“火抗降低 30%”和“全元素抗性降低 15%”时，火抗只降低 30%；其他属性降低 15%。
- `direct:true` 是固定/真实式结算入口，会跳过常规抗性、增减伤与暴击，应谨慎使用。
- 护盾先于生命承受伤害。
- 伤害统计按物理、火、水、冰、雷、风分别记录。
- 元素反应伤害归属于后手触发反应的角色。

核心函数：

- `effectiveAtk(unit)`：动态攻击力。
- `outgoingDamageModifier(unit, target)`：攻击方增伤。
- `incomingDamageModifier(target, source)`：目标减伤/易伤。
- `damage(source, target, raw, options)`：统一伤害入口。
- `healUnit(target, amount, source)`：统一治疗入口。

等级、星级和装备系统应修改“传入 `damage()` 前的面板与原始倍率”，不要绕过统一伤害入口。

## 8. 索敌、移动与攻击

- 单位优先保留仍然存活的当前目标。
- 否则按六边形距离选择最近敌人。
- 同距离默认随机；存在双手剑时优先选择双手剑。
- 不按剩余生命值选低血目标。
- 寻路会寻找可到达攻击位置，并在当前目标被队友堵住时尝试其他目标，避免永久卡死。
- 长柄攻击距离 2；单双手剑 1；法器 4；弓 5。
- 普攻动画在各自命中时刻调用 `resolveHit()`，远程攻击不是发射时立刻结算。

## 9. 元素与附着

元素：火、水、冰、雷、风。物理仅作为伤害类型，不作为可残留附着。

- 元素附着没有持续时间，被反应消耗前一直存在。
- 普通物理攻击不附着。
- 法器普攻造成对应元素伤害，但八重神子普攻不附着；心海普通状态也不附着。
- 技能是否附着由技能逻辑明确决定。
- 风元素用于触发扩散，不会作为残留附着。
- 无附着的元素伤害不能触发后续反应。

## 10. 元素反应

| 反应 | 组合 | 当前效果 |
|---|---|---|
| 蒸发 | 火 + 水 | 目标增伤变为 -10%，持续 5 秒 |
| 感电链 | 水 + 雷 | 连接同阵营附近最多两个带水/雷附着目标 8 秒，传递 10% 承受伤害；参与连线的附着被消耗 |
| 冻结 | 水 + 冰 | 攻速降低 20%，持续 5 秒；第二次冻结额外完全控制 3 秒并重置累计 |
| 融化 | 火打冰 / 冰打火 | 本次总伤害 ×2.0 / ×1.5；目标减伤变为 -10%，持续 3 秒 |
| 超载 | 火 + 雷 | 半径 1.5 格固定 200 点范围伤害；伤害属性取后手元素，不附着且不能再次触发反应 |
| 超导 | 冰 + 雷 | 中心格及周围六格形成 15 秒领域；敌人首次进入失去 10 法力，每个领域对每个单位最多触发一次 |
| 扩散 | 风 + 已附着元素 | 原目标和附近敌人对应元素抗性降低 30%，其他属性降低 15%，持续 5 秒；受到触发者 100% 攻击力的对应元素伤害且不附着 |

反应入口：`attachAndReact(source, target, baseDamage)`。

## 11. 当前角色技能摘要

### 胡桃（火 / 长柄，20/60）

- 消耗当前生命 30%，进入 8 秒【彼岸蝶舞】。
- 攻击提高 100%，减伤 20%，普攻转为火伤，状态期间普攻不回蓝。
- 状态后的第 1 次普攻立即追加 200% 攻击火伤并附着；之后每 3 击再次触发，即第 1、4、7……击。
- 每场首次受到致死伤害时保留 1 生命，自动进入状态并获得 2 秒无敌。

### 珊瑚宫心海（水 / 法器）

- 进入 8 秒【海人化羽】。
- 普攻额外加入最大生命 6% 的水元素基础伤害。
- 每第三击附着水元素。
- 每次强化普攻为生命比例最低友军治疗心海最大生命 8%。

### 申鹤（冰 / 长柄）

- 为本场累计伤害最高的两名存活队友增加申鹤当前攻击力 40% 的攻击，持续 8 秒，不叠加但刷新。
- 对最近两个敌人造成 80% 攻击冰伤并附着。

### 菲谢尔（雷 / 弓，20/60）

- 首次释放在相邻空格召唤不可受击的奥兹。
- 每次释放获得 3 秒雷伤普攻，并永久增加 0.2 攻速，可多次叠加至 5.0。
- 菲谢尔每攻击 4 次，奥兹造成 120% 攻击雷伤并附着。
- 该特殊状态是明确例外，仍按普通规则通过普攻回蓝。

### 琴（风 / 单手剑）

- 在自身格和周围六格创建 8 秒【蒲公英领域】。
- 每 2 秒为领域内所有友军治疗 100，共 4 次。
- 每名敌人首次进入时受到 1 点可触发扩散的风伤。

### 早柚（风 / 双手剑）

- 立即自疗 400，进入 6 秒状态并减伤 20%。
- 每 2 秒清除一次自身元素附着，不触发反应。
- 状态期间普攻不回蓝。

### 安柏（火 / 弓）

- 向敌人最密集处投掷兔兔伯爵。
- 释放 1 秒后对半径 1.5 格造成 400% 攻击火伤并附着。

### 优菈（冰 / 双手剑）

- 目标进入 1 格范围后，对三格扇形造成 50% 攻击冰伤并附着。
- 获得 300 护盾 5 秒；有盾期间普攻不回蓝。
- 护盾自然结束时，以剩余盾值对自身相邻敌人造成等额冰伤并附着；被打破不反击。

### 妮露（水 / 单手剑，15/25）

- 第 1、2 次技能：当前目标受到 200% 攻击水伤并附着。
- 第 3 次：三格扇形造成 120% 无附着水伤；再发射贯穿水刃。
- 水刃首个目标受到 400% 攻击水伤，后续每个目标是前一个的 70%，全部附着。

### 八重神子（雷 / 法器，10/40）

- 普攻固定 10 点雷元素基础伤害，不附着，主要用于回蓝。
- 同阵营多名八重神子共享杀生樱数量，最多三株；召唤物生成在备战席，没有空位时保持满蓝。
- 普通杀生樱独立每 2 秒造成召唤者 70% 攻击雷伤，每第二次攻击附着。
- 第三株出现时全队杀生樱升阶至 105% 倍率；同队所有八重神子清空法力、上限变为 100 并切换大招。
- 大招对敌方全体造成 400% 攻击雷伤并附着，永久施加 30% 重伤。

### 木桩

- 2000 生命、40 抗性、无攻击、无移动、无蓝条。
- 生命归零后立即回满，不死亡，用于持续测试。

## 12. 统计与界面

统计项：

- 造成伤害与各伤害属性构成；
- 承受伤害与各伤害属性构成；
- 有效治疗量；
- 实际吸收的护盾量。

伤害属性在同一横行展示并用颜色区分。选中角色时，右侧动态面板展示当前生命、法力、护盾、攻击、攻速、暴击、暴伤、抗性、距离、增伤、减伤、武器特性和技能说明。技能说明默认简略，可切换详细。

## 13. 经济和等级系统的推荐数据分层

不要继续让一个 `unit` 对象同时代表配置、玩家资产和战斗状态。建议拆成三层：

### 13.1 角色模板 `PieceTemplate`

```js
{
  templateId: 'hutao',
  name: '胡桃',
  element: '火',
  weapon: '长柄',
  tier: 4,              // 商店品质或费用档
  cost: 4,
  baseStats: { hp: 1000, atk: 60, resist: 30, as: 1.1, range: 2 },
  mana: { initial: 20, max: 60 },
  skillId: 'hutao_butterfly'
}
```

模板是只读数据，不保存位置、当前生命或临时状态。

### 13.2 玩家棋子实例 `OwnedPiece`

```js
{
  instanceId: 'piece-123',
  templateId: 'hutao',
  ownerId: 'player-blue',
  star: 1,
  level: 1,
  xp: 0,
  location: { kind: 'bench', index: 0 },
  equipment: []
}
```

这是购买、出售、合成、升级和持久化的对象。

### 13.3 战斗运行时 `BattleUnit`

由 `PieceTemplate + OwnedPiece + 战斗增益` 在开战时创建。当前 `makeUnit()` 应逐步改造成：

```js
createBattleUnit(template, ownedPiece, formationState)
```

战斗结束后不要把当前生命、法力、目标、元素附着、临时攻速或技能计数写回玩家资产。

## 14. 经济系统推荐边界

建议新增玩家状态：

```js
{
  playerId,
  gold,
  playerLevel,
  playerXp,
  shopSlots,
  shopLocked,
  ownedPieces,
  winStreak,
  loseStreak,
  round
}
```

推荐流程：

```text
回合结算 → 基础收入/利息/连胜连败 → 商店刷新 → 购买/出售/合成/升级 → 布阵 → 战斗 → 回合结算
```

接入注意事项：

1. 当前无限仓库应保留为“开发者调试模式”，正式模式隐藏或禁用。
2. 正式棋子必须由商店购买后创建唯一 `instanceId`。
3. 商店库存与棋池共享数量若要实现，应独立于战斗单位数组 `units`。
4. 备战席仍为 10 格；购买时无空位应拒绝购买或进入待领取区，不能静默覆盖。
5. 右键删除应在正式模式改为出售，并按星级/费用计算返还金币。
6. 双击上下场、拖动交换、阵营判定可以继续复用。
7. 木桩和召唤物不能进入商店、棋池、出售或升星逻辑。
8. 多名同名角色允许同时上场；八重神子的同队共享召唤计数必须继续按阵营统计。

## 15. 等级与升星系统推荐边界

必须先确定“玩家等级”和“棋子等级”是否同时存在：

- 玩家等级：控制上场人口、商店品质概率。
- 棋子星级：通过同名棋子合成，放大基础面板。
- 棋子等级：若保留，应通过经验单独成长；不要与星级重复承担同一种成长功能。

推荐最小版本先只做玩家等级 + 棋子星级：

```text
3 个 1 星同名棋子 → 1 个 2 星
3 个 2 星同名棋子 → 1 个 3 星
```

推荐把倍率集中在一个函数中，不要散落到技能代码：

```js
function statsForStar(base, star) {
  const hpMultiplier = [0, 1, 1.8, 3.2][star];
  const atkMultiplier = [0, 1, 1.5, 2.25][star];
  return {
    ...base,
    hp: Math.round(base.hp * hpMultiplier),
    atk: Math.round(base.atk * atkMultiplier)
  };
}
```

这些只是初始建议，不是已经确定的平衡数值。抗性、攻速、攻击距离、技能控制时间通常不建议随星级直接增长，否则高星单位会同时获得生存、输出和机制优势，难以平衡。

技能倍率目前直接读取 `effectiveAtk()`、`maxHp` 或固定值，因此：

- 攻击和生命成长会自然放大大部分技能；
- 固定值技能（超载 200、早柚治疗 400、琴治疗 100、优菈护盾 300）不会随星级成长；
- 接入升星前必须决定固定值是否读取角色星级系数；
- 建议为固定值增加统一的 `scaleFixedValue(baseValue, battleUnit)`，避免逐个技能硬编码。

## 16. 推荐的代码拆分顺序

1. 把 `pieceTemplates`、技能说明、武器数据和反应数据移到 `data/`。
2. 把 `makeUnit()` 拆为模板读取、成长计算、战斗实例创建。
3. 保持 `damage()`、`healUnit()`、`attachAndReact()` 为统一结算入口。
4. 将阵容保存从纯位置数组升级为玩家资产 + 位置引用。
5. 新增 `EconomySystem`、`ShopSystem`、`ProgressionSystem`，不要写进 `tick()`。
6. `tick()` 只负责已经开始的战斗；经济、购买与升级只在备战阶段运行。
7. 最后再增加商店 UI、金币、经验、人口与回合界面。

## 17. 必须保持的兼容规则

- 开战时锁定并保存最终站位。
- 战斗结束返回时恢复开战前站位。
- 返回备战不清空上一场统计；新战斗开始才清空。
- 备战席单位不战斗。
- 战斗运行时的移动位置不能覆盖备战阵容位置。
- 元素附着在被消耗前永久存在。
- 反应伤害归后手触发者。
- 超载范围伤害不附着、不能继续触发反应。
- 攻速上限 5.0。
- 特殊状态默认阻止普攻回蓝，除非角色规则明确例外。
- 仓库、备战席、棋盘上的同名棋子必须通过唯一实例 ID 区分。

## 18. 验收建议

经济与等级系统接入后至少验证：

- 购买后实例 ID 唯一，重复角色互不覆盖；
- 出售只删除目标实例，不删除同名角色；
- 合成后位置、装备和阵营归属正确；
- 开战和返回备战不会复制或吞掉棋子；
- 升星面板与实际伤害一致；
- 固定值技能是否成长符合设计决定；
- 八重神子共享杀生樱计数仍按阵营工作；
- 召唤物不占棋池、不参与合成和出售；
- 木桩只在调试模式可用；
- 刷新页面后经济、等级、阵容和实例仍能正确恢复；
- 旧的 `element-auto-chess-formation-v4` 数据能迁移或被明确清理，不能半读取造成幽灵棋子。

## 19. 素材与发布提醒

当前项目包含基于现有游戏角色和图标制作的原型素材，适合作为内部设计验证与玩法测试。若要公开发布、商业化或上架平台，应重新确认角色、图标、名称和相关素材的使用授权，或替换为拥有完整权利的原创素材。
